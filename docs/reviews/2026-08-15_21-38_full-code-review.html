01Critical findings

Fixed

SessionFilter silently swapped SQL parameters

sessions.go · args() vs buildSessionsQuery

Bind arguments were appended in the order Day, ParentID, ByID while the WHERE clauses were emitted as ByID, Day, ParentID. Any filter combining ByID with Day or ParentID bound the day string to id = ? and the session ID to the date comparison — returning zero rows with no error. Reproduced before the fix: SessionFilter{ByID: "fixture-root", Day: fixtureDay()} returned ∅.

Fix buildSessionsQuery now returns (query, args) with each condition and its placeholder appended in the same branch, making drift structurally impossible. The ByID doc now states filters compose. Regression test: TestSessionsByIDComposesWithOtherFilters (sessions_test.go).
Fixed

AgentGraph sibling order followed updated_at, not created_at

agents.go · childSessions / reverseByCreated

The documented contract is preorder with “each subtree ordered by creation time”. The implementation reversed the sessions listing (ordered updated_at DESC), which yields updated_at ASC — created order only when the two correlate. Reproduced before the fix: siblings created +1s/+2s but touched in reverse order came back misordered, and the helper’s comment (“flips newest-first into oldest-first”) laundered the lie.

Fix Replaced by sortByCreated: a slices.SortFunc on CreatedAt with the session ID as deterministic tiebreak. Regression test: TestAgentGraphSiblingsOrderedByCreatedNotUpdated (agents_test.go) uses anti-correlated timestamps.

02Minor findings

Fixed

Package doc contradicted the tested day-filter semantics

doc.go:27-31

doc.go claimed day filters “compare against the UTC calendar day of created_at”. That is half the truth: the filter value is formatted in its own location, as pinned by TestSessionsDayFilterUsesDayLocation and documented precisely on SessionFilter.Day. A split brain between package doc and field doc.

Fix Rewrote the Timestamps section to state both halves: created_at compares as its UTC day; the filter value contributes its own location.
Fixed

Stale Nix vendorHash broke nix flake check

flake.nix:57

Commit 16260fe refreshed transitive dependencies (go.sum) without updating vendorHash; the go-modules fixed-output derivation mismatched. CI never noticed because it installs golangci-lint directly instead of using the flake (commit ed5ac2c).

Fix Updated to the derivation’s reported hash; verified via nix build .#default.goModules. Full nix flake check additionally requires rows.go to be committed (untracked files are invisible to the flake’s git source filter).
Fixed

Fixed

Redundant map re-assignment in dedupe

discover.go:232

Ticketed

Open cannot be cancelled

db.go:48 · TODO_LIST

Open probes the schema on context.Background(). Six fast local queries make this harmless today; a future OpenContext would let callers bound startup on slow filesystems (NFS).

Ticketed

AgentGraph is N+1

agents.go · TODO_LIST

One query per node. Fine for realistic graphs (depth cap 64, small fan-out), and the recursion buys the depth guard; a recursive CTE is the escalation path if a consumer ever reports it hot.

Ticketed

Session.Todos is an untyped JSON string

types.go:33 · TODO_LIST

The field carries an opaque JSON blob. json.RawMessage (or a decoded type) would make “this is structured data” explicit at the type level — a breaking-ish change to bundle with the next minor.

Ticketed

Capability probe cannot distinguish missing from broken

schema.go:97-127 · TODO_LIST

tableExists/columnExists return false on query errors, so an I/O-broken database masquerades as a legacy schema and reads degrade silently. An acceptable tolerant-reader tradeoff, but worth a strictness decision later.

04Strengths

+
Schema-drift defense is exemplary Capability probing at Open + zero-value substitution + MissingColumns() for user warnings: absent columns never fail reads, and the required-table check fails loudly with a typed error.
+
Sealed Part union Unexported isPart() closes the set; unknown discriminators pass through as UnknownPart with the raw payload. Forward compatibility by construction, verified by fuzzing.
+
Parity contract on the analytics SQL TestStatsParityWithCrushDailySQL re-runs the historical collector SQL verbatim and requires identical numbers, so refactors cannot silently change reported statistics.
+
Read-only proven, not promised TestOpenIsReadOnly hashes crush.db + WAL/SHM sidecars before and after a full read pass. The strongest possible statement of the library’s core safety claim.
+
Dual-schema fixtures generated per test current + legacy DDL with the same seed data: every read is exercised against both shapes without committed binary testdata.
+
Error taxonomy Five sentinels + one typed error; caller errors returned unwrapped with self-contained messages; every wrap names the database path.

05Verdict

Production-ready for its stated scope

A small, sharp, single-purpose library doing exactly what it promises: typed, tolerant, provably read-only access to an undocumented, drifting schema. The two correctness bugs were in the newest, least-tested seams (filter composition, subtree ordering), not in the core paths. With both fixed and pinned by regression tests, coverage at 86%+, race detector clean, ~90 linters silent, and the remaining findings ticketed in TODO_LIST.md, the codebase leaves this review stronger than it entered.
