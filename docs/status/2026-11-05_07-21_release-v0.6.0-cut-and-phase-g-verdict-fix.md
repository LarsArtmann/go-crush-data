## d) TOTALLY FUCKED UP

1. **The amend incident (the real one).** Sequence: (i) I batched
   `check-doc-links.sh && git add … && git commit && git push` — the guard
   failed on my un-backticked `[0.6.0]` bracket, so **the `git add` never ran**
   and my citation-fix commit never existed. (ii) Four of five citation fixes
   sat uncommitted; AGENTS.md's edit was the only staged file. (iii) On retry I
   ran `git commit --amend` — silently **adopting the daemon's already-pushed
   commit `97b3918`** as my base and rewriting pushed history locally
   (`5da8d45`), producing a non-fast-forward rejection. Recovery was clean
   (`git reset --soft origin/master`, recommit as `b626d9e`, fast-forward push)
   — no work lost, no force-push — but the root cause was mine: amending in a
   repo where HEAD is routinely a daemon commit that is already pushed, without
   checking HEAD's identity first. Both hazards are now AGENTS.md gotchas.
2. **Lost background shell.** The first `verify-all.sh` background job was
   killed by a tool-call interruption; one full gate cycle was re-run. Cheap,
   but avoidable sequencing (don't long-block on `job_output` for a gate that
   nothing else depends on mid-session).
3. **`be70b78` SHA déjà vu.** The session-start snapshot already listed a
   commit with my exact verdict-fix message/SHA while this tree demonstrably
   still had the bug (the fix applied and verified here). Most likely a parallel
   session converged on the same one-line fix. Not damage — but it's the second
   time this session that history-surface state and tree state disagreed; the
   AGENTS.md concurrent-session rules are what kept it harmless.

## e) WHAT WE SHOULD IMPROVE

1. **Ban amend as a habit here** (now an AGENTS.md rule): new commits only;
   inspect `git log -1` (Daemon trailer, author, pushed?) before any
   history-modifying command.
2. **Stage/commit as standalone verified steps**, never chained behind a guard
   command whose failure silently cancels staging (now an AGENTS.md rule).
3. **Release checklist should include a FEATURES-row check**: every new shipped
   API gets an inventory row *before* the tag, not after (b1/c5 gap).
4. **Citation sweep belongs in the release cut itself**, not as a follow-up
   commit — the changelog cut invalidates `[Unreleased]` claims everywhere at
   the same instant.
5. **Tag the release commit, not HEAD** — this session got that right
   (`f65db74`), after a daemon commit landed mid-wait; keep it deliberate.
6. **Don't block on background gates mid-session**; poll instead of
   `job_output wait` so an interruption can't vaporize the job.
7. **pkg.go.dev banner**: for v0.7.0, check it as a final step after ~30 min,
   or accept it as known eventual lag and stop chasing it.
